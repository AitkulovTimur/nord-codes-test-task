# Nord Codes API Tests

Автотесты API приложения Nord Codes методом чёрного ящика.

1) Тестируемое приложение запускается с помощью стандартных средств Java, как процесс OS
2) Мокаем внешний сервис, к которому обращается данное приложение. С использованием WireMock
3) Отправляем запросы через RestAssured
4) Работаем с отчетом и генерируем его, используя Allure.

## Стек

- Java 17
- JUnit 5
- RestAssured
- WireMock
- Allure
- Maven
- GitHub Actions

## Что покрывают тесты

- успешный и неуспешный `LOGIN`;
- повторный `LOGIN` с тем же токеном;
- `ACTION` без предварительного `LOGIN`;
- успешный `ACTION` после `LOGIN`;
- ошибку `ACTION`, если внешний сервис вернул ошибку;
- `ACTION` после неуспешного `LOGIN`;
- успешный `LOGOUT`;
- `ACTION` после `LOGOUT`;
- `LOGOUT` без активной сессии;
- отсутствие и неверное значение API-ключа;
- неверный формат токена;
- неизвестный тип действия;
- отсутствие обязательных параметров.

## Как запустить

Требования:

- Java 17
- Maven 3.8+

Запуск тестов:

```bash
mvn clean test
```

---
## Как открыть Allure-отчёт локально
```bash
mvn allure:serve
```
Чтобы сгенерировать статический отчёт:
```bash
mvn allure:report
```

## Как работает CI
GitHub Actions запускает тесты при каждом push в ветку `main` и публикует Allure-отчёт на GitHub Pages.

## Особенности
По заданию токен должен состоять из 32 символов `A-Z` и `0-9`.

Во время тестирования выяснилось, что приложение проверяет токен по другому правилу:

```text
^[0-9A-F]{32}$
```
